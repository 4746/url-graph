# URL Graph

Плагін Obsidian, який показує напрямлені зв’язки між Markdown-нотатками за URL з YAML frontmatter. Граф працює в окремій вкладці та не змінює стандартний граф Obsidian.

## Використання

1. Додайте нотаткам властивість `url` з одним абсолютним HTTP або HTTPS URL:

   ```yaml
   ---
   title: "QR Code Pricing | FbFast"
   url: "https://fbfast.io/pricing"
   language: "en"
   ---
   ```

2. У тілі іншої проіндексованої нотатки додайте посилання:

   ```markdown
   [Pricing](https://fbfast.io/pricing)
   ```

3. Увімкніть **URL Graph** у **Settings → Community plugins**.
4. Виберіть значок розгалуження на лівій бічній панелі або команду **URL Graph: Open graph**.

Коліщатко або жести змінюють масштаб, перетягування фону переміщує граф, перетягування вузла змінює його положення. Натискання на вузол відкриває відповідну нотатку в новій вкладці. Стрілка вказує від нотатки з посиланням до його цілі.

Кнопка **Fit graph** показує весь граф, **Arrange nodes** повторно розташовує вузли, а **Rebuild index** повторно сканує Vault. Доступна також команда **URL Graph: Rebuild URL index**. Панель показує кількість нотаток, зв’язків і файлів, які не вдалося прочитати або розібрати.

## Налаштування

У **Settings → URL Graph → URL property** вкажіть точну назву властивості frontmatter. Назва чутлива до регістру; порожнє поле використовує `url`. Зміни зберігаються в даних плагіна та автоматично перебудовують індекс. Вкладені властивості та списки URL у першій версії не підтримуються.

### Мова інтерфейсу

За замовчуванням URL Graph використовує мову Obsidian. У **Налаштування → URL Graph → Мова** (англійською **Settings → URL Graph → Language**) можна вибрати **English**, **Українська** або автоматичний режим **Використовувати мову Obsidian**.

Вибір зберігається незалежно від мови Obsidian. Кнопки й повідомлення відкритого графа, налаштування, команди та підказка на бічній панелі змінюють мову одразу. Граф при цьому не перебудовується: масштаб і положення вузлів зберігаються. Для непідтримуваної мови Obsidian або відсутнього ключа перекладу використовується англійська. Автоматичний режим повторно перевіряє мову під час повернення до вікна Obsidian й відкриття налаштувань; сам Obsidian може вимагати перезапуску після зміни своєї мови.

Після встановлення оновленого `main.js` один раз перезавантажте плагін або Obsidian, щоб завантажити новий код. Подальше перемикання мови плагіна перезапуску не потребує. Кнопка перебудови індексу не перезавантажує код плагіна.

### Вигляд і фільтри графа

У попапі **Налаштування графа** (іконка повзунків на панелі графа) доступні лише параметри відображення:

| Параметр | Варіанти / діапазон | За замовчуванням |
| --- | --- | --- |
| Показувати стрілки | Показувати або приховувати стрілки на кінцях єдиної лінії між вузлами | Увімкнено |
| Показувати підказку вузла | Назва нотатки та вхідні / вихідні зв’язки при наведенні | Увімкнено |
| Групувати вузли за розміром | Радіальна градація для розміру за кількістю зв’язків | Увімкнено |
| Показувати ізольовані нотатки | Показувати або приховувати вузли без ребер після фільтрації | Показувати |
| Підписи вузлів | Завжди, при наведенні або виборі, приховані | Завжди |
| Назва вузла | Назва файлу, шлях у сховищі, URL | Назва файлу |
| Розмір вузлів | Однаковий, за кількістю вихідних або вхідних зв’язків | Однаковий |
| Відстань між вузлами | 40–300, бажана відстань розкладки | 110 |
| Товщина ребер | 0,5–5 | 1,5 |
| Непрозорість ребер | 0,1–1; менше значення означає більшу прозорість | 0,7 |
| Кольори вузлів | Колір теми, власний колір, за доменом або батьківською папкою | Колір теми |

Власний колір вибирається окремою палітрою й використовується в режимі **Власний колір**. Кольори груп призначаються стабільно з вбудованої палітри; різні піддомени та різні повні шляхи батьківських папок є окремими групами.

Кожна пара вузлів з’єднана однією прямою: зі стрілкою на одному кінці для одностороннього зв’язку або на обох кінцях для взаємного. При наведенні підсвічується спільна лінія та лише вихідна стрілка вибраного вузла. Кількість зв’язків, розміри вузлів і списки вхідних/вихідних посилань враховують обидва напрямки взаємного зв’язку окремо.

Іконка **Налаштування графа** на його панелі відкриває вікно параметрів відображення. У полі **Розмір вузлів** можна вибрати однакові кружки, розмір за кількістю вихідних або вхідних зв’язків. Параметри відображення доступні тільки в цьому попапі й не дублюються в загальних налаштуваннях. Зміни зберігаються й одразу застосовуються до відкритого графа без переіндексації.

Сусідні дії панелі графа також представлені іконками: вписати граф у вікно, розташувати вузли, перебудувати індекс і показати зв’язки. При наведенні з’являються локалізовані підказки; кнопки також мають доступні назви для роботи з клавіатури й читачів екрана. У попапі зарезервовано місце під смугу прокручування та додано внутрішній відступ.

Для розміру враховуються унікальні напрямлені ребра поточного відфільтрованого графа. Повторні посилання між тією самою парою нотаток рахуються один раз. Діаметр зростає плавно від 22 до максимум 64 одиниць; вузли без відповідних зв’язків залишаються найменшими. Розкладка повторно обчислюється при зміні фактичних діаметрів, а перевірка перекриттів враховує нові розміри.

Коли **Групувати вузли за розміром** увімкнено й вибрано розмір за вхідними або вихідними зв’язками, граф розташовує вузли за спаданням відповідного числа: від найбільших у центрі до менших на зовнішніх кільцях. Подібні значення опиняються поруч; враховується фактична кількість навіть після досягнення максимального діаметра. Перевірка перекриттів зберігається. Вимкнення групування повертає розкладку за зв’язками. Для однакового розміру групування не застосовується.

Тултіп вузла показує назву нотатки та **Вхідні / Вихідні** для поточного видимого графа, включно з активними фільтрами або локальною областю. Перемикач **Показувати підказку вузла** приховує його незалежно від підписів вузлів. Обидва нові перемикачі зберігаються та застосовуються без перезапуску.

У режимі кольору теми вузли мають нейтральний колір. При наведенні курсора фіолетовим підсвічуються поточний вузол і всі його безпосередні сусіди за вхідними та вихідними зв’язками. Також підсвічуються його вихідні ребра та їхні стрілки; вхідні ребра залишаються звичайними. Коли курсор залишає вузол або область графа, початкові кольори й прозорість відновлюються. Підсвічування діє також поверх власних кольорів і кольорів груп.

У загальних налаштуваннях плагіна, в розділі **Фільтри графа**, є списки включення та виключення папок і доменів. Вони не відображаються в попапі оформлення. Вказуйте один запис на рядок і натисніть **Застосувати фільтри**. Некоректні записи блокують застосування всіх чотирьох списків із повідомленням про помилку.

- Папка `blog` включає `blog/a.md` і `blog/sub/b.md`, але не `blogger/c.md`. Шляхи вказуються від кореня Vault і чутливі до регістру. `/` означає лише нотатки в корені Vault.
- Домен `example.com` включає також `sub.example.com`, але не `notexample.com`. Регістр і типовий порт не впливають на зіставлення; порт не використовується у фільтрі. Маски `*` та шляхи сторінок не підтримуються.
- Порожній список включення не обмежує граф. Виключення мають пріоритет; умови папок і доменів діють одночасно.
- Ребра до прихованих вузлів теж приховуються. Якщо вимкнути ізольовані нотатки, вузол зникне також тоді, коли всі його сусіди були відфільтровані.

Налаштування відображення не перечитують Vault і не змінюють правила зіставлення URL. Зміни оформлення зберігають положення видимих вузлів, масштаб і зміщення. Зміна відстані або складу вузлів/ребер запускає розкладку; нові вузли можуть змінити положення сусідів. При наведенні мишею або виборі вузла в режимі підписів при наведенні показується його підпис; вибір доступний також на сенсорному екрані.

Відстань у налаштуваннях є базовою: для великих і щільних графів вона автоматично збільшується максимум до ×1,25. Розкладка розділяє незв’язані групи, а додатковий запас між областями вузлів обмежено 16–28 одиницями. У режимі постійних підписів резервується місце за їхніми виміряними розмірами; зміна підписів запускає повторний розрахунок. Після основної розкладки окремий прохід розсуває вузли, чиї області кружків або постійних підписів перекриваються. Ця перевірка виконується у Worker, а в резервному режимі — порціями. Для деталей використовуйте масштабування й переміщення. Ручне перетягування дозволяє самостійно змінювати отримане розташування.

### Локальний граф у вкладці

Натисніть правою кнопкою на вузол і виберіть **Відкрити локальний граф**. Відкриється нова вкладка з вибраною нотаткою, нотатками, на які вона посилається, та нотатками, які посилаються на неї. Показуються тільки ребра, що безпосередньо з’єднані з кореневою нотаткою; зв’язки між її сусідами й подальші переходи не додаються. Коренева нотатка виділена та зазначена над графом.

Кожна локальна вкладка має власну кореневу нотатку, масштаб і розкладку. Перехід до іншої Markdown-нотатки не змінює її корінь. Шлях кореня зберігається в стані робочого простору; перейменування та зміни індексу враховуються автоматично. Якщо корінь видалено або він більше не має проіндексованого URL, з’являється пояснення.

Поточні фільтри й налаштування відображення плагіна діють також у локальному графі. Розміри вузлів за кількістю зв’язків рахуються в межах видимої локальної групи. Пункт контекстного меню доступний і в локальній вкладці — так можна відкрити зв’язки будь-якого її вузла в іншій вкладці. Основний граф і бічна панель залишаються окремими переглядами.

### Панель URL-зв’язків

Натисніть правою кнопкою на вузол графа й виберіть **Показати зв’язки**. У правій бічній панелі відкриються списки **Вихідні** та **Вхідні** з кількістю зв’язків, назвами й повними шляхами нотаток. Вибраний вузол, його сусіди й вихідні ребра залишаться підсвіченими після відведення курсора. Кнопка **Прибрати підсвічування графа** повертає звичайний режим наведення.

URL-зв’язки відкриваються у власній вкладці з іконкою розгалуження, поряд зі стандартними вкладками Obsidian, не замінюючи їх. Після оновлення виконується одноразове відновлення стандартної вкладки вхідних посилань, якщо попередня версія замінила її вкладкою URL-зв’язків. Відновлення можливе, коли вбудований додаток вхідних посилань увімкнений; наступні навмисні закриття вкладки поважаються.

Списки оформлено як окремі акордеони з лічильниками. Типово **Вихідні** розгорнуто, **Вхідні** згорнуто; стан кожного зберігається при перемиканні нотаток та оновленні панелі. Назва нотатки й шлях показуються окремими рядками. Іконка прицілу праворуч від запису показує ціль на графі; іконка рамки біля поточної нотатки вміщує всю групу, а гумка біля заголовка прибирає закріплене підсвічування. Усі іконки мають текстові підказки та доступні з клавіатури.

Натискання на назву в списку відкриває нотатку. **Показати на графі** переміщує граф до цілі, зберігаючи список зв’язків початкової нотатки. **Показати всі зв’язки на графі** вміщує вибраний вузол та його видимих безпосередніх сусідів у вікно. Перехід чекає завершення фонового розташування, якщо воно ще триває. Звичайний клік на вузол графа, як і раніше, відкриває нотатку.

Щоб переглядати зв’язки під час читання нотаток, відкрийте панель командою **URL Graph: Відкрити URL-зв’язки** (англійською **Open URL connections**). Далі вона автоматично оновлюється при відкритті іншої Markdown-нотатки; відкривати граф не потрібно. На панелі самого графа теж є кнопка **Показати зв’язки**.

Кнопка **× Закрити URL-зв’язки** біля заголовка закриває цю вкладку та скидає вибір і закріплене підсвічування. Вона доступна й у порожній панелі. Перехід до іншої Markdown-нотатки оновлює список і скидає попереднє закріплення; перехід до іншого типу перегляду очищує старий список. При перемиканні між URL-графом і панеллю вибраний вузол зберігається.

Панель використовує повний URL-індекс незалежно від фільтрів графа. Відфільтровані нотатки позначаються, а перехід до них на графі недоступний, доки ви не зміните фільтри. Відкривати ці нотатки зі списку можна. Показ усієї групи попереджає, якщо частина сусідів прихована. Фільтри автоматично не скидаються. Для нотатки без проіндексованого URL відображається пояснення; зв’язки за звичайними wiki-посиланнями або непроіндексованими зовнішніми URL сюди не додаються.

### Фільтри за властивостями frontmatter

У **Налаштування → URL Graph → Властивості для фільтрації** вкажіть назви полів через кому, наприклад `language, category, status`. Для кожного поля в панелі самого графа з’явиться окремий список із варіантом **Усі значення** та значеннями з frontmatter проіндексованих нотаток. Порожнє поле налаштування вимикає ці фільтри. Повторні назви і зайві пробіли ігноруються.

Наприклад, вибір `de` у списку `language` та `published` у списку `status` показує нотатки, у яких одночасно `language: "de"` і `status: "published"`, та ребра між цими нотатками. Фільтри працюють разом з обмеженнями папок, доменів та ізольованих вузлів. Вибір зберігається й застосовується без повторного читання файлів; розкладка обчислюється у фоні.

Підтримуються рядки, числа, логічні значення та YAML-списки таких значень. Наприклад, для `tags: [seo, pricing]` можна вибрати `seo` або `pricing`. Числа й логічні значення показуються як текст; рядки очищаються від пробілів на початку та в кінці. Назви полів і значення чутливі до регістру. Об’єкти, вкладені списки, `null` і порожні значення не додаються до варіантів. Нотатки без значення поля залишаються видимими, якщо для нього вибрано **Усі значення**. Підтримуються точні назви полів верхнього рівня, а не шляхи до вкладених властивостей.

Зміна переліку полів перебудовує індекс. Видалення поля з налаштування прибирає його фільтр та збережений вибір. Списки значень автоматично оновлюються при зміні, створенні й видаленні нотаток та формуються з повного URL-індексу незалежно від поточного відбору. Якщо вибране значення зникло, воно залишається з позначкою **немає в індексі** до зміни вибору. Нотатки без проіндексованого URL не додають значень до списків.

Типово використовується `language`, щоб зберегти попередню поведінку; це звичайна налаштовувана властивість. Збережений вибір попереднього фільтра мови переноситься автоматично. Мова інтерфейсу плагіна налаштовується окремо. Метадані використовуються лише для відбору вузлів; зв’язки, як і раніше, створюються виключно за URL.

## Правила зіставлення

- Вузли — лише Markdown-нотатки з коректним рядковим HTTP(S) URL у налаштованій властивості. Нотатки без нього не створюють вузлів чи ребер.
- Нотатки без зв’язків теж відображаються. Однакові назви файлів не впливають на зіставлення; вузли визначаються повним шляхом.
- URL нормалізуються однаково для frontmatter і посилань: ігноруються фрагменти `#…` та завершальні `/` шляху, нормалізуються регістр хоста й типовий порт.
- Протокол, регістр шляху та query-параметри зберігаються. HTTP і HTTPS, різні query-параметри або їхній порядок не об’єднуються. Редиректи не перевіряються.
- Підтримуються Markdown-посилання, посилання через визначення, автопосилання `<https://…>` та відкриті URL. HTML-сутності в адресах Markdown-посилань декодуються.
- Зображення, блоки й фрагменти коду, HTML-коментарі, коментарі Obsidian `%%…%%`, frontmatter і внутрішні wiki-посилання не створюють зв’язків. HTML-теги `<a>` не аналізуються.
- Посилання на відсутні в індексі URL ігноруються. Повторні посилання між тією самою парою нотаток дають одне ребро. Ребра від нотатки до самої себе не створюються.
- Якщо кілька нотаток мають один нормалізований URL, створюється ребро до кожної з них.

## Оновлення та приватність

Початкове сканування починається після готовності робочого простору Obsidian. Створення, редагування, перейменування та видалення файлів автоматично оновлюють граф із затримкою близько 350 мс після серії подій. Звичайне редагування перечитує лише змінені файли; перейменування й зміна налаштування запускають повне сканування. Одночасно читається не більше восьми файлів.

Під час відкриття графа, перебудови індексу й розташування вузлів показується індикатор завантаження. Він повідомляє поточний етап, а під час читання — кількість оброблених файлів. Повторні натискання кнопок графа тимчасово заблоковані. Старі дані графа зберігаються до завершення перебудови; решта інтерфейсу Obsidian залишається доступною.

Читання файлів, побудова зв’язків і додавання елементів графа виконуються порціями з передаванням керування інтерфейсу. Розкладка Cytoscape обчислюється в локальному Web Worker; він включений у `main.js` і не потребує додаткового файла або мережі. Якщо середовище не підтримує worker, використовується покрокова розкладка між кадрами. Закриття графа скасовує його незавершену підготовку й розрахунок координат. Відкриття графа використовує готовий індекс і саме по собі не запускає повне сканування Vault.

Плагін працює локально, не робить мережевих запитів, не завантажує URL, не збирає телеметрію та ніколи не записує Markdown-файли або frontmatter. На диск записуються лише власні налаштування плагіна. Cytoscape.js, Marked та декодер HTML-сутностей включені в `main.js`; CDN і зовнішні сервіси не потрібні.

## Встановлення та розробка

Потрібен Obsidian **1.8.7+** (офіційний API визначення мови `getLanguage()`). Використовується npm; для розробки потрібен Node.js **20+** (рекомендовано актуальну LTS-версію).

```sh
npm install
npm run dev
npm test
npm run lint
npm run build
```

Для локального встановлення помістіть `main.js`, `manifest.json` і `styles.css` у `<Vault>/.obsidian/plugins/url-graph/`, перезавантажте Obsidian та увімкніть плагін. Цей проєкт уже розміщений у відповідній папці плагінів.

`main.js` генерується esbuild у корені плагіна і не додається до Git. Для релізу ці три файли потрібно додати окремими assets; тег релізу має дорівнювати версії з manifest без префікса `v`.

Код розділено на модулі: `src/graph/` — нормалізація й зіставлення, `src/indexing/` — читання та кеш індексу, `src/ui/` — Cytoscape view, `src/settings.ts` — налаштування, `src/main.ts` — життєвий цикл плагіна. Автоматичні тести перевіряють логіку й події через підмінений Obsidian API; ручна перевірка графа в Obsidian потрібна окремо, зокрема на мобільних пристроях.

### Додавання локалізації

Власна реалізація i18n міститься у `src/i18n/` і не додає зовнішніх залежностей. Усі тексти інтерфейсу розташовані у `src/i18n/locales/`; англійський словник `en.ts` визначає типізовані ключі.

1. Створіть файл мови, наприклад `src/i18n/locales/fr.ts`, експортуйте словник з тими самими ключами. Використайте `satisfies Partial<Dictionary>` з типом із `./en` для неповного перекладу або `satisfies Dictionary` для повного.
2. Збережіть плейсхолдери `{notes}`, `{links}` та `{errors}` у відповідних перекладах.
3. Імпортуйте словник у `src/i18n/locales/index.ts` і додайте до `locales` запис `fr: { nativeName: 'Français', translations: fr }`.

Нова мова автоматично з’явиться у виборі, валідації налаштувань і визначенні мови Obsidian. Основну логіку плагіна змінювати не потрібно. Назви нотаток і дані Vault не перекладаються.
